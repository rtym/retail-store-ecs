Business goals — business-goals/

IDGoal (short)File
BG-1The account owner and the sample-app maintainers (ST-1, ST-6) need a working, representative polyglot microservice store running on Amazon ECS with AWS managed backing services so that container and managed-service patterns on AWS can be demonstrated, learned and evaluated.BG-1
BG-2Shoppers (ST-5) need to browse, search, fill a cart and check out so that every completed checkout produces a stored order — the storefront's functional purpose.BG-2
BG-3The account owner (ST-1) needs the environment's running cost to stay proportionate to a demonstration / non-production workload so that the shared account's budget is not consumed by it.BG-3
BG-4The account owner and the security function (ST-1, ST-4) need the environment to protect shopper data, detect misuse and recover from failure so that it can stay exposed on the public internet inside a shared account — and, if ST-1 decides so, be promoted beyond demonstration use — without unacceptable risk.BG-4

Prioritised driver list (input to ADD / ATAM)

  1. AQA-2 (H,H) — Loss of Availability Zone eu-central-1a
  2. AQA-1 (H,M) — Single task failure of the storefront
  3. RQA-1 (H,M) — Restore after data corruption or deletion
  4. SQA-2 (H,M) — Containment of a compromised service
  5. SQA-1 (H,L) — Shopper traffic confidentiality in transit
  6. SQA-3 (H,L) — Detection of suspicious control-plane activity
  7. OQA-1 (H,L) — Operators learn of failures before shoppers
  8. UC-1 — Browse product catalogue: Dominant read load; crosses the internet trust boundary; exercises Service Connect and the catalogue database.
  9. UC-2 — Search products: Extends UC-1 conditionally (feature flag); adds a second data store to the catalogue service — a consistency and availability concern.
  10. UC-3 — Manage shopping cart: State-changing; the only data path that leaves the VPC (to a regional AWS endpoint), making it depend on the NAT Gateway.
  11. UC-4 — Check out: Carries PII across three services; the synchronous chain ui → checkout → orders → databases is the longest call path.
  12. UC-5 — Place order: The integration point of the system (asynchronous event); the only use case that writes PII to a database; included by UC-4.
  13. CON-2 (hard) — Amazon ECS on AWS Fargate
  14. CON-3 (hard) — Upstream pre-built images, version 1.6.3
  15. CON-4 (hard) — Backing services limited to supported providers
  16. CON-5 (hard) — Upstream: educational use, not production
  17. SCQA-1 (M,H) — Demand spike
  18. PQA-1 (M,M) — Catalogue page responsiveness
  19. PQA-2 (M,L) — Provisioned capacity is used
  20. DQA-1 (M,L) — Safe rollout of a bad version
  21. MQA-1 (M,L) — Swap a backing-service provider
  22. INQA-1 (M,L) — Add a consumer of order events
